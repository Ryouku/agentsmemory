# Task ADR-001-T2: Build the risk–coverage curve, the calibration file, and the go/no-go gate

**Depends-on:** T1
**Covers:** none — no spec
**Estimated scope:** M (multi-file)
**Owner:** unassigned
**Produces:** `palace.RiskCoverage` (curve over the three populations), `palace.Calibration` (thresholds + fingerprint file, load and save), `agentsmemory eval --calibrate` with `--gate`
**Consumes:** `EvalCaseResult.Population` / `TopRerank` / `RerankScored` and `palace.AbsentVerification` (T1)

## Goal

Turn the labelled scores into a risk–coverage curve, two boundaries and a fingerprinted calibration file — and make the ADR's declared go/no-go criterion an exit code rather than a reading of a table.

## Affected Files

| File | Change | Why |
|------|--------|-----|

## Ordered Steps

1. Write the failing tests first (TDD red): `TestRiskCoverageRecommendsThresholds` over a fully separable synthetic distribution where both boundaries are known, plus an overlapping one where the recommendation must honour the declared recall target and refuse-allowance rather than maximise accuracy, and one where the two rules select the same threshold so the band is empty and reported as such; `TestGateFailsBelowDeclaredBar` asserting the gate verdict is false when the Wilson lower bound on refusal misses 0.30 and true when it clears it; `TestCalibrateRefusesUnverifiedCases` asserting a case file holding an absent case without T1's verification provenance, or one generated by `--style absent-easy`, prints its curve but writes no calibration file and exits non-zero. Commit them red.
2. Implement the curve in `internal/palace/evalstats.go` over the labelled rows: for each candidate threshold, answer-recall on the **reachable**-answerable rows (`RerankScored` true; the score is the production arm's top-1, which is what the served gate will compare) and correct-refusal rate on verified-absent rows. Unreachable rows are counted and reported, never scored as answerable.
3. Derive the two boundaries from the one curve. `answer_at` is the highest threshold holding answer-recall ≥ `--answer-recall` (default 0.95) on the reachable-answerable rows. `refuse_below` is the highest threshold at which at most `--refuse-allowance` reachable-answerable rows score below it (default 1 — at allowance 0 the recorded distributions make the band provably empty, since the lowest answerable score, −6.569, sits below the lowest absent one, −6.327). The second is a count rather than a rate because a rate cannot express it here: with ~39 reachable-answerable cases the achievable recall grid is 1.0, 0.974, 0.949, so a 0.975 target and a 0.95 target select the same threshold and the band collapses. Print the recall each chosen threshold actually achieves next to the target it was asked for; `refuse_below ≤ answer_at` follows from recall being non-increasing in the threshold.
4. Print how many verified-absent cases fall **below** `refuse_below`. The boundary sits just under the answerable low tail by construction, so the count may be small; when it is zero the `no_answer` verdict can never fire on evidence like this sample's, and the report must say so in as many words: the design is three verdicts on this corpus, not four.
5. Implement `--gate`: exit 0 when, at `answer_at`, the 90% Wilson lower bound on the correct-refusal rate over verified-absent cases is ≥ 0.30; exit non-zero otherwise, printing the observed rate, the bound, the case count and the target. The bound, not the point estimate, is the comparison — at n≈20 the point estimate carries roughly ±0.11 at one standard error, and a gate that ignores that would pass on noise.
6. Score the canary set for the fingerprint: a fixed list of (query, document) pairs, scored `canaryRepeats = 5` times through the configured reranker. Record the pairs, the mean score per pair, and the **largest deviation observed across the repeats** as the tolerance — derived from the instrument, never typed. Deterministic inference yields a zero spread and therefore an exact-match check at startup.
7. Write the calibration file: both thresholds, the sample counts, the targets, the gate verdict, and the fingerprint — canary pairs, scores and derived tolerance; whether the observed scores are bounded in (0,1) or unbounded (the transform is *inferred* from the canary scores, because `Reranker.Rerank` returns floats and does not report which dialect decoded them); the operator-declared `--rerank-model` label; and the ranking profile in force (fusion mode, BM25 weight and auto flag, closet scale, rerank pool, rerank weight). The requested `limit` is deliberately absent: it arrives per call, and T5 compares it against the recorded rerank pool per request instead. The file is what T4 loads and validates, and its short content hash (`Calibration.ID`) is what names this operating point in telemetry, so rows judged under two different calibrations are never pooled as one population.
8. Make that refusal print rather than abort: an unverified or easy-negative set still gets its curve on stdout, because T3 has to compare the two regimes side by side; what it does not get is a calibration file, a recommended threshold or a zero exit.
9. Run the acceptance command; all four tests green.

## Invariants

- Unreachable-answerable cases are never counted as answerable.
- A calibration file is only written when every absent case in the set carries T1's verification provenance.
- The canary tolerance is measured at calibration time; no epsilon is typed into the source.
- The tool writes a calibration file, never configuration: an operator still has to point the server at it, so a bad calibration cannot become production behaviour by itself. This replaces the earlier plan, where the command printed a threshold for the operator to paste — a pasted float arrives without the fingerprint that makes it checkable, which is the whole point of the file.

## Risks

- With ~20 verified-absent cases the recommended thresholds are unstable. Mitigation: the report prints the counts and the Wilson interval beside every rate, and the gate compares the bound rather than the estimate.
- The canary's spread is measured on one machine under one load; a busier host could exceed it and turn a healthy reranker into `unknown` verdicts. Mitigation: T4 degrades to `unknown` on a canary mismatch instead of refusing to serve, and the mismatch is logged with both score sets so it is diagnosable rather than mysterious.

## Stop Condition

Stop if the curve cannot be computed because too few rows carry a scored top-1 — a set where the production arm rarely reranked is measuring a path nobody will serve, and the fix is upstream in T1's generation rather than here.

## Out of Scope

- Running the gate against the real corpus and acting on it — that is T3's job.
- Loading or validating the calibration at startup — that is T4's job.
- Applying a threshold automatically (permanent: an operator wires the file, so a bad calibration cannot silently become production behaviour).
- A learned multi-feature abstention model over the same rows (deferred: docs/adr/BACKLOG.md)
