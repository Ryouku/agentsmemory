## Per-task workflow

Every task follows the same order:

1. Derive the universe from the production structure and print the initial residual set.
2. Add observations before production fixes; reproduce each residual red where possible.
3. Fix one residual per logical commit.
4. Compile and run a wire-cut/default-flip mutant against the named observation.
5. Run the focused axis, then the full clean-tree fence.
6. Commit the residual report and mutation evidence generated by the runner, not a prose-only claim.

## Shared acceptance fence

```bash
gofmt -l cmd internal clients | grep -q . && exit 1
go vet ./...
go test ./... -count=1
go build ./...
```

T2–T4 additionally run their axis report and require no unacknowledged residual. T5 does not authorise edits in another repository; each pilot runs in the repository that owns it, with that project’s intent and memory loaded.

## Decision points that block behaviour, not the harness

The runner may record these as `policy_undecided`; implementation must stop rather than choose silently:

- concurrent update/delete semantics (ADR-010 ownership);
- whether any MCP operation is admin-only rather than writer-level;
- whether inbox/recall changes push during a running session;
- what geometry a fake embedder must preserve before ranking results may rely on it.

They do not block closing the five current MCP lifecycle gaps or building the runner.
