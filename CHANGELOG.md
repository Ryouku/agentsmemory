ADR-016 stamps entities **on the write path**, so a memory an agent files finally carries the entities the derived graph is built from — with the caveat that `RecomputeGraph` reads that column and never re-extracts, so **every drawer written before this release stays outside the graph permanently** and the backfill remains unbuilt; four shipped ranking defaults flipped after measurement — `FUSION` linear→`rrf`, `CLOSET_BOOST` 1→`0`, `RERANK_POOL` 50→`10`, `RERANK_TIMEOUT` 90s→`10s`, the last being the sharpest single fix here since a budget longer than any client will wait meant the degradation path could never fire and the caller died holding nothing while a usable page sat one fallback away — all four reversible by environment alone with no redeploy (`FUSION=linear CLOSET_BOOST=1` restores the previous profile exactly), and an always-on `ranking:` startup line plus `am_status.ranking` report the profile actually in force, which is worth reading once after upgrading; and the review that landed this contributed the last four commits — a doc-default gate that now derives its universe from the `Config` struct instead of naming two of five fields (`BM25Weight` had no coverage anywhere and changing it broke nothing), a knowledge-graph scope test that fails instead of skipping so the behaviour it records cannot change in silence, and `doctor --roles`, which counts every key the guard refuses and says whether each is a decision someone made or a row nobody repaired, since promoting a teammate and fixing broken data are not the same action

**Upgrading to this release:** no migration (`db/` is byte-identical to v0.0.91), no re-embed, no re-index, and rollback is clean — verified by running the previous binary against a database this one had written. Two things are not automatic: **run `agentsmemory doctor --roles` and promote any `member`-role key whose agent files memories**, and decide whether to accept the new ranking profile or pin `FUSION=linear CLOSET_BOOST=1`. Optionally run `doctor --index` for pre-existing payload drift, and have one writer-role agent per workspace call `am_recompute_graph` so newly stamped memories reach the graph.

## v0.0.96 — 2026-08-25

Everything merged since v0.0.95 (`67c8170`, 2026-08-24) lands here: PRs #33, #37, #40, #25, #38, #39, #42, #45, #44, #46 and #43 — fifteen merges, tagged in one go because nothing between them was tagged.

**Read this section before upgrading.** Three shipped behaviours changed and none of them had a note until now: two defaults and one removal. ADR-014 says the shipped default is the measured one; it also means a default that changes owes the operator a sentence before they discover it — and a setting that is *deleted* owes them more than that.

- **`am_kg_query` now returns only facts that are still true.** Previously a query named an entity and got back every fact ever recorded about it, retracted ones included, tagged `current:false` and left for the reader to honour — `current` appeared in every response and in no request. An agent that acted on a retracted fact was simply wrong, and nothing on the server prevented it. The new default is `status:"current"`, filtered server-side so what it removes never reaches the context window. **Nothing is hidden silently:** any response that filtered something carries `withheld: {"ended": N}` and a hint naming the parameter that restores it, because a session about to redo a rejected thing is precisely the session that does not know to ask for history. To restore the old behaviour per call, pass `status:"all"`; `status:"ended"` is the audit direction, for asking what the team has changed its mind about. Measured on the live graph at 1,363 triples the immediate saving is small — 47 expired facts, 3.4% — and this ADR does not rest on it; it rests on the default being correct, and on a ratio that only ever grows.

- **`am_search` returns the whole memory, not the matched chunk** (ADR-024, shipped earlier and still unannounced). Callers that assumed a chunk-sized payload now receive up to a whole memory — measured at 9,056 runes where a chunk was 1,600. `snippet_chars` bounds it; `snippet_chars: 0` asks for the whole memory explicitly.

- ⚠ **Three hook environment variables were REMOVED, not deprecated** (#46): `AGENTSMEMORY_SESSION_REPORT`, `AGENTSMEMORY_STATS_URL` and `AGENTSMEMORY_STATS_BASE`. They were three names for one endpoint and two off-switches for one behaviour, and the Stop hook now reads none of them. **If you set any of these, it stops doing anything the moment you upgrade — silently, because an unread variable cannot warn you.** There is one origin and one off-switch now; check your hook configuration rather than assuming it carried over. `TestRetiredStatsEnvVarsAreNotRead` in `clients/claude-code` keeps them retired.

Also changed, and worth knowing before it surprises you:

- **`am_update_drawer` refuses content over 4,000 runes** (#39, #40). `Update` re-embeds its whole content as ONE vector and never re-chunks, so a memory created small and grown in place was the one input that could exceed the embedder's window — and the TEI client asks for truncation, which means the server answered 200 with a vector for the *prefix*. The tail stayed stored, still came back from `am_get_drawer`, and was simply unfindable. Silent, and only on that path. The bound is deliberately conservative headroom rather than a measured ceiling for bge-m3 (which holds far more): it is sized so that pointing `EMBED_BACKEND` or `OLLAMA_EMBED_MODEL` at a smaller model stays survivable. It does not make every model safe — a 512-token model such as `mxbai-embed-large` tops out around 2k characters and 4,000 would still cut it. To correct a memory larger than the bound, delete it and file it again.

Also in this release: `am_kg_query` gains a **`predicate`** argument that works as an entry point in its own right — supply it without an entity to ask "every fact of this relation", which is how you audit what the team has changed its mind about, and which used `idx_kg_triples_team_predicate`, an index that had existed unused since the graph was built. Facts now return **`recorded_at`**, **`source_drawer_id`** and **`source_file`**, three columns written on every fact since day one and returned by nothing; `recorded_at` is transaction time, so the graph can finally answer "what did we *know* on D" and not only "what was true on D".

**Upgrading to this release:** one additive migration (`00025`, a `CREATE INDEX`, no data rewrite, no re-embed, no re-index) and rollback is a `DROP INDEX`. Nothing about the write path, storage semantics, ranking or drawers changed.

Three things are not automatic, in the order they will bite you:

1. **Check your hook environment for the three retired variables above.** This is the only change that goes silent rather than loud — nothing reads them, so nothing complains.
2. **If an integration depends on `am_kg_query` returning retracted facts, pin `status:"all"` at the call site.** Responses that filtered something say so via `withheld` and a hint, so this one announces itself.
3. **If a caller assumed `am_search` returned a chunk-sized payload, set `snippet_chars` explicitly.** The default is a window over the whole memory now, not over the matched chunk.

**If you query the past, read this one.** `as_of` is unchanged, but it now *composes* with the new default rather than standing alone. The two answer different questions — `status` asks whether a fact was ever retracted, `as_of` asks whether it was in effect at an instant — so `as_of` on its own now returns **open-ended facts that were also in effect on that date**, not every fact in effect on it. A point-in-time snapshot needs both: `as_of:"2026-01-31", status:"all"`. This is the quietest edge of the change, because the call still succeeds and the answer still looks like history.
